# 🚌 BusTopia

**BusTopia** is a term project for the **Software Engineering** course (CSE Term 3-2).  
It presents the complete planning, designing, and documentation of a robust **Bus Ticket Booking, Scheduling, and Live Tracking System**.

---

## 🚀 Overview

BusTopia aims to revolutionize the bus journey experience by introducing a smart, efficient, and user-friendly system. It enables users to:

- 📍 Track buses live on a map  
- 🎟️ Book tickets in advance  
- 🧠 Detect smart routes based on current traffic  
- ⏱️ Estimate probable arrival and destination times  

---

---

## 📘 Design Diagram Descriptions

### 1. 📊 BPMN Diagram (Business Process Model and Notation)

Describes the **end-to-end business process** of the system.  
It captures how users interact with the system, the flow of actions, and decision points — giving a high-level operational view of how BusTopia functions.

---

### 2. 🧪 Use Case & Test Cases

- **Use Case JSON & PDF:** Lists all probable user interactions and functionalities.
- **Test Cases:** Demonstrate various scenarios and expected outcomes to ensure feature reliability.

These documents ensure functional coverage and support testing for reliability and completeness.

---

### 3. 🖥️ Mock UI

A basic, visually guided prototype showing how the application may look and feel.  
It helps both the design team and stakeholders understand the proposed interface and flow of user actions.

---

### 4. 📐 Class Diagram

Represents the **structure of the system** in terms of its classes, attributes, methods, and relationships.  
Essential for developers to understand how different parts of the system interact with one another on a code level.

---

### 5. 🤝 Collaboration Diagram

Shows how **different objects interact** with each other over time to perform a particular functionality.  
It focuses on the flow of messages between objects in a specific scenario, ensuring coordination and communication are logically planned.

---

### 6. 🏗️ Layered Architecture

Describes the **logical layering** of the system (e.g., presentation, business logic, data access).  
It defines clear responsibilities for each layer and promotes modularity, making the system maintainable and scalable.
